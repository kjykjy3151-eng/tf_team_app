# 팀 편성 웹 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공고(`참고자료/공고.pdf`)대로 학생이 스스로 팀을 편성하고, 마감 뒤 남은 학생을 AI가 배정하며 앱이 규칙으로 검사하는 Streamlit 앱을 만든다.

**Architecture:** 규칙 판단은 DB를 모르는 순수 함수(`tf/rules.py`)로 두고, DB를 읽고 쓰는 동작(`tf/service.py`, `tf/auth.py`, `tf/roster.py`, `tf/ai.py`)은 psycopg 연결을 인자로 받는다. 화면(`tf/ui_*.py`)은 이 함수들을 부르고 결과 문자열을 `result` 컨테이너에 보여 줄 뿐이다. 한 팀을 바꾸는 동작은 트랜잭션 안에서 `tf_teams` 행을 `FOR UPDATE`로 잠가 순서대로 처리한다.

**Tech Stack:** Python 3.13, Streamlit 1.66 이상(`st.container(key=...)`, `st.fragment(run_every=...)`), Supabase PostgreSQL(Session pooler 주소), psycopg 3 + psycopg-pool, bcrypt, requests, python-dotenv, tzdata, pytest, GitHub Actions.

**Spec:** `참고자료/공고.pdf`(기준), `docs/PRD.md`(공고를 정리한 것).

## Global Constraints

- 기준은 `참고자료/공고.pdf`다. 공고와 다르게 해야 할 것 같으면 구현을 멈추고 사용자에게 묻는다.
- 비용 0원: AI는 이름이 `:free`로 끝나는 모델만 부른다. `openrouter/free`는 쓰지 않는다. DB, 배포, GitHub Actions는 무료 범위 안에서만 쓴다. 비용이 생길 수 있는 작업은 하기 전에 묻는다.
- Streamlit key는 `docs/PRD.md` 7절(공고 2.7절) 표와 한 글자도 다르지 않게 쓴다: `login_student_no`, `login_password`, `login_submit`, `whoami`, `result`, `team_{번호}`, `apply_{번호}`, `vote_yes_{지원자 학번}`, `vote_no_{지원자 학번}`, `admin_roster_file`, `admin_team_count`, `admin_start`, `admin_close`, `unassigned`, `admin_assign`, `assign_status`, `admin_confirm`. `refresh`는 쓰지 않는다(자동 갱신을 하므로).
- 표에 없는 위젯의 key도 영문, 숫자, 밑줄만 쓴다(예: `admin_use_ai`).
- `result` 안내는 "승인", "대기", "거절", "막힘" 가운데 하나로 시작하고 `: 이유`를 붙인다. 예: `막힘: 같은 주 역할의 팀원이 있음`
- 키와 관리자 비밀번호는 코드에 쓰지 않는다. 로컬은 `.env`, 배포는 Streamlit Secrets에서 `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD` 이름으로 읽는다. 값은 화면, 로그, 오류 메시지, 대화에 출력하지 않는다. 있는지 확인할 때는 "있음, 없음"만 출력한다.
- 화면에 보이는 시각은 한국 시간(`Asia/Seoul`)이다.
- 연습용 시나리오의 학생 이름, 학번, 순서에 맞춘 코드는 쓰지 않는다(시나리오는 `tests/`에서만 쓴다).
- 테이블 이름은 모두 `tf_`로 시작한다.
- 한국어 문구: 가운뎃점 대신 쉼표를 쓴다. `result`, `assign_status` 안내는 공고 예시처럼 "~음", "~함"으로 끝내고 마침표를 붙이지 않는다.
- 새 파일 첫 줄에 생성 일시 주석(`# YYYY-MM-DD HH:MM KST`)을 단다. 시각은 `date -u -d "+9 hours" "+%Y-%m-%d %H:%M"`으로 확인한다.
- 단계가 끝날 때마다 커밋하고 **멈춰서 사용자 확인을 받는다.** 다음 단계는 사용자가 시작하라고 할 때 시작한다.
- 모든 커밋 전에 `.venv/Scripts/python scripts/check_secrets.py`를 실행해 `비밀값: 없음`을 확인한다(Task 1에서 만듦). "있음"이면 커밋하지 않고 멈춘다. (공고 4.1, 6.3절 7번)
- 화면에 예외 메시지나 traceback을 그대로 보여 주지 않는다. `st.exception`을 쓰지 않고, DB, AI 오류는 `막힘: DB 오류({예외 종류 이름})`처럼 종류만 보여 준다. 오류 메시지에 DB 주소가 섞일 수 있기 때문이다. (공고 6.3절 8번)
- 코드, 테스트, 문서, 화면 캡처에 실제 사람(수강생 포함)의 이름이나 학번을 쓰지 않는다. 테스트 명단은 공고의 가상 이름(가나다, 학생1 등)만 쓴다. (공고 6.3절 9번)
- 로그인은 학번과 비밀번호로만 한다. 구글 로그인(`st.login`)은 쓰지 않는다. (공고 3장)

## Review Focus

1. **AI 배정 중 자동 갱신이 실행을 끊음**: `st.fragment(run_every=3)`의 다시 그리기가 최대 6분 걸리는 AI 배정 실행을 중간에 끊으면 배정이 사라진다. 관리자는 배정이 끝날 때까지 기다리고 결과를 봐야 한다. → 4단계 Step 9에서 가짜 모델이 15초 걸리게 해 브라우저로 확인한다.
2. **풀이 쥔 연결이 끊김**: 배포 서버에서 오래 쉬면 Supabase가 연결을 닫는다. 다음 화면에서 오류 없이 다시 연결해야 한다. → 1단계 `test_pool_recovers_after_connection_killed`.
3. **CSV의 공백과 빈 줄**: 엑셀에서 저장한 CSV는 값 앞뒤 공백, 끝의 빈 줄, `;` 앞뒤 공백이 있을 수 있다. 잘 읽혀야 하고, 틀린 역할 이름은 몇 행인지 알려 주며 막아야 한다. → 2단계 `test_parse_roster_strips_spaces_and_blank_lines`, `test_parse_roster_rejects_unknown_role`.
4. **자동 갱신 뒤 `result`가 사라짐**: 3초마다 다시 그려도 마지막 결과 안내가 남아야 한다(채점 프로그램이 읽기 전에 사라지면 안 됨). → 5단계 Step 3 브라우저 확인.
5. **새로 들어온 팀원의 투표**: 내 지원 뒤 다른 지원자가 먼저 승인되면 그 사람의 찬성도 있어야 승인된다. → 3단계 `test_new_member_must_also_vote`.

**Interfaces:**
- Produces:
  - `tf.config.ROLES: tuple[str, ...] = ("기획자", "웹 프로그래머", "프론트엔드 디자이너", "테스터", "보고서 작성자", "발표자")`

  - `tf.config.get_secret(name: str) -> str | None`: `st.secrets`에 있으면 그 값, 없거나 secrets 파일이 없으면 `load_dotenv()` 뒤 `os.getenv(name)`. 값을 출력하지 않는다.
  - `tf.config.to_kst(dt: datetime) -> str`: `"%Y-%m-%d %H:%M:%S"` 한국 시각
  - `tf.db.get_pool() -> psycopg_pool.ConnectionPool`: `@st.cache_resource`로 프로세스에 한 번 만든다. `min_size=1, max_size=4, check=ConnectionPool.check_connection`. 풀은 연결을 다시 쓰므로 "연결은 한 번 만들어 다시 씀"(공고 4.2)을 지킨다. 세션마다 스레드가 다르므로 연결 하나를 같이 쓰지 않고 풀에서 빌린다.
  - `tf.db.apply_schema(conn) -> None`: `schema.sql`을 실행한다.
  - `tests/conftest.py`의 픽스처 `conn`: `DATABASE_URL`로 연결해 `tf_test_<임의 8자>` 스키마를 만들고 `SET search_path`, `apply_schema` 뒤 넘겨 주고, 끝나면 스키마를 지운다. `DATABASE_URL`이 없으면 skip. 실제 `tf_` 테이블(public)은 건드리지 않는다.
  - 픽스처 `connect`: 같은 임시 스키마를 `search_path`로 둔 새 연결을 돌려주는 함수(동시 지원 테스트용)

공고 5장 최소 참고안 그대로에 아래를 더한다. 스키마 이름을 붙이지 않는다(테스트가 `search_path`로 임시 스키마에 만들 수 있게).

- `tf_members(team_id int references tf_teams on delete cascade, slot_no int check (slot_no between 1 and 4), student_id int unique not null references tf_students on delete cascade, primary key (team_id, slot_no))`
- `tf_applications(id serial pk, team_id int not null references tf_teams on delete cascade, student_id int not null references tf_students on delete cascade, status text not null check (status in ('대기','승인','거절')), reason text, created_at timestamptz not null default now(), decided_at timestamptz)`

- `tf_settings(key text primary key, value text not null)` — `closed` = `'true'`/`'false'`

  - `tf.rules.join_block_reason(team: Team, applicant: Student) -> str | None`: 차례대로 검사해 첫 이유를 돌려준다.
    1. `len(members) >= TEAM_MAX` → `"팀이 꽉 참"`
    2. 주 역할이 같은 팀원 있음 → `"같은 주 역할의 팀원이 있음"`
    3. `TEAM_MAX - (len(members) + 1) < unfilled_required(members + [applicant])` → `"필수 포함 역할을 맡을 학생의 자리가 모자람"`
  - `tf.service.load_state(conn) -> State`

    - 마감 → `막힘: 모집이 마감됨`
    - 이미 팀 있음 → `막힘: 이미 팀이 있음`
    - 대기 중 지원 있음 → `막힘: 결과를 기다리는 지원이 있음`
    - `join_block_reason` → `막힘: {이유}`

    - 팀원 추가가 `UniqueViolation`이면(동시 도착) 롤백 뒤 `거절: 다른 학생이 먼저 자리에 들어감`을 기록하고 돌려준다.

    - 투표자가 지금 그 팀원이 아님 → `막힘: 이 팀의 팀원만 투표할 수 있음`
