# 팀 편성 웹 앱 (DSMP 중간 과제)

학생들이 팀 프로젝트용 팀을 스스로 편성하고, 모집 마감 뒤 남은 학생은 AI가 배정하며 앱이 그 배정을 규칙으로 검사하는 Streamlit 앱입니다. 기준 문서는 과제 공고이며, 아래 항목 번호는 공고 7.1절 양식을 따릅니다.

## 1. 배포 주소

https://tf-team-app-2026.streamlit.app

## 2. PRD와 구현 계획의 위치

- PRD: [docs/PRD.md](docs/PRD.md)
- 구현 계획: [docs/구현 계획.md](docs/구현%20계획.md)
- DB 테이블: [schema.sql](schema.sql) (모든 테이블 이름이 `tf_`로 시작, 유일성 제약과 `password_hash` 열 포함)

## 3. 고른 해결 방법 (공고 3장)

8가지 기능 모두 **어려운 해결**로 만들었습니다.

| 기능 | 고른 해결 | 구현 위치 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결: `st.fragment(run_every=3)`로 팀 목록, 지원, 투표 부분만 3초마다 다시 그림 | `tf/ui_student.py`, `tf/ui_admin.py` |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결: 지원할 때 남는 자리 수가 못 채운 필수 포함 역할 수보다 적으면 막음(기획자와 웹 프로그래머는 서로 다른 학생으로 셈) | `tf/rules.py`의 `join_block_reason`, `unfilled_required` |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결: 모든 팀원이 찬성한 순간 규칙을 다시 검사하고, 어기면 거절함. 처리 순서는 투표가 끝난 순서 | `tf/service.py`의 `vote` |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결: `tf_members`의 `(team_id, slot_no)` 기본 키와 `student_id` 유일성 제약, 팀 행 잠금 | `schema.sql`, `tf/service.py` |
| AI 응답이 늦을 때 | 어려운 해결: 모델마다 요청을 보낸 때부터 120초 전체 시간을 재서, 응답이 오는 중이어도 끊고 다음 모델로 넘어감(`requests`의 timeout에만 맡기지 않음) | `tf/ai.py`의 `call_model` |
| 3차 모델까지 실패 | 어려운 해결: 검사 다섯 가지를 모두 통과하는 배정을 모든 경우를 따져 찾음(백트래킹) | `tf/rules.py`의 `solve_assignment` |
| AI 대기 중 화면 | 어려운 해결: `assign_status`에 "1차 모델(…)의 응답을 기다리는 중"처럼 몇 차 모델을 기다리는지 보여 줌 | `tf/ai.py`의 `assign`, `tf/ui_admin.py` |
| DB(Supabase)가 일시정지되지 않게 | 어려운 해결: GitHub Actions 예약 실행으로 매일 09:00(KST)에 `SELECT 1` | `.github/workflows/keep-db-awake.yml`, `scripts/ping_db.py` |

## 4. 쓴 모델 3개

1차 `nvidia/nemotron-3-ultra-550b-a55b:free`, 2차 `google/gemma-4-31b-it:free`, 3차 `poolside/laguna-s-2.1:free`

- 모두 이름이 `:free`로 끝나는 무료 모델입니다. 코드가 `:free`가 아닌 모델과 `openrouter/free`는 부르지 않습니다(`tf/ai.py`의 `_is_free`).
- 처음에는 시범 앱과 같은 `nvidia/nemotron-3-super-120b-a12b:free`를 1차로 정했으나, 10/27 시험 때 제공 서버가 멈춰 있어(HTTP 404, 가동률 0%) 바꿨습니다. 3차로 정했던 `thinkingmachines/inkling:free`는 HTTP 403("only available on agentic harnesses")이라 `poolside/laguna-s-2.1:free`로 바꿨습니다.

## 6. 클로드가 잘못된 추론이나 답변을 한 사례

1. **공고와 다른 DB를 권함.** 공고 4.2절은 "6장 실습에서 만든 Supabase 프로젝트를 재사용"하라고 하는데, 클로드는 공고를 확인하지 않고 DB 주소를 받는 방법으로 Neon을 권했고, 그 주소로 접속 시험까지 마쳤습니다. PRD를 공고와 대조하라고 시켰을 때 클로드가 4.2절을 읽고 스스로 이 잘못을 알렸고, Supabase로 바꾼 뒤 1단계를 시작했습니다. `docs/PRD.md`(커밋 `88ce439`)의 11.1절에 Supabase 재사용 원칙을 적어 두었습니다.
2. **Secrets 없이 먼저 배포되면 관리자 계정이 끝까지 만들어지지 않는 버그.** 클로드는 관리자 계정을 앱 시작 때 한 번만 만들려고 결과를 `st.cache_resource`로 저장했는데, 비밀번호가 없을 때의 결과(`False`)까지 저장했습니다. 배포할 때 Secrets가 빈 채로 먼저 배포되었고, 그 뒤 Secrets를 넣어도 배포한 앱 화면에 "관리자 비밀번호 설정: 없음"이 계속 보여서 알아챘습니다. 비밀번호가 있을 때만 저장하도록 커밋 `56cb1de`에서 고쳤고, 다시 배포된 뒤 안내가 사라진 것을 확인했습니다.
3. **결과 안내가 다시 그리는 동안 비어 보임.** 처음 구현에서는 `result`를 화면 끝에서 채워서, `st.rerun()`으로 실행이 중간에 멈추면 다음 실행이 끝날 때까지 몇 초 동안 빈칸이었습니다. 4단계에서 AI 배정을 브라우저로 시험하며 결과 안내를 0.5초마다 기록하다가 알아챘고, 커밋 `e8f851a`에서 실행 시작 때 바로 채우도록 고쳤습니다.

## 7. 앱에서 발견한 문제점

1. **확정 뒤 결과 안내가 바뀌지 않은 경우가 한 번 있었음.** 배포한 앱에서 부록 3(어려움) 15단계의 "배정안 확정"을 눌렀을 때, DB에는 확정이 저장되었고(모든 팀 4명, 규칙 검사 통과, 3초 갱신 부분의 "팀이 없는 학생 0명"도 바뀜), `result`는 30초가 넘도록 이전 안내("승인: 2차 모델의 배정안이 검사를 통과함")에 머물렀고 배정안 표도 남아 있었습니다. 같은 단추를 다시 누르자 "막힘: 배정안이 지금 상태와 맞지 않음…"이 나와, 처음 확정 뒤의 세션 처리(결과 저장, 배정안 지우기)가 끝까지 되지 않았음을 확인했습니다. 쉬움, 중간 시나리오의 확정에서는 정상이었고, Streamlit Cloud 로그에도 오류가 없어 원인을 아직 찾지 못했습니다. 채점 프로그램이 이 순간 `result`를 읽으면 기대와 다른 안내를 볼 수 있습니다. (화면 캡처는 남기지 못했고, 브라우저 자동 조작 기록과 DB 확인 결과가 근거입니다.)
   - 조사(10/29): 로컬에서 65초 걸리는 AI 배정 뒤 확정을 단계별 서버 로그와 함께 해 보았지만 재현되지 않았습니다. Streamlit 소스를 읽어 "3초 자동 갱신이 실행 중인 확정을 끊는다", "브라우저 연결이 끊기면 실행이 멈춘다"는 두 가설은 아님을 확인했습니다. 원인은 아직 확정하지 못했습니다.
   - 방어 수정(10/29): (1) 관리자 화면이 실행마다 자동 갱신 부분을 새로 만들던 것을 한 번만 정의하도록 바꿈. (2) 화면에 남은 배정안의 학생이 이미 그 팀에 들어가 있으면(확정이 저장됨) 배정안을 지우고 `result`를 "승인: 배정을 확정함(n명)"으로 고침. 같은 일이 다시 생겨도 관리자의 다음 동작 때 화면이 DB와 맞춰집니다. 로컬에서 DB에만 확정을 저장해 이 상태를 일부러 만든 뒤, 다음 동작에서 바로 고쳐지는 것을 확인했습니다.
2. **무료 AI 모델이 느리거나 자주 실패함.** 1차 모델이 120초를 넘긴 일이 세 번 있었고, 2차, 3차 모델은 HTTP 429가 잦았습니다(5항의 기록). 실패 처리 덕분에 배정은 늘 끝나지만, 관리자는 최대 2분 넘게 기다려야 합니다. 1차 모델을 더 빠른 모델로 바꾸는 것을 검토해야 합니다.
3. **명단을 다시 올려도 이전 명단의 학생 화면이 로그인된 채 남음.** 부록 2(중간)를 마친 뒤 부록 3(어려움) 명단을 올렸을 때, 학생 탭은 이미 없어진 학생2(2026202)로 로그인된 채 빈 팀 목록을 보여 주었습니다. 그 상태에서 누르면 "막힘: 명단에 없는 학번임"이 나오므로 규칙은 지켜지지만, 로그아웃되도록 하는 편이 낫습니다.

## 실행 방법 (로컬)

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\streamlit run streamlit_app.py
```

`.env`에 `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`가 있어야 합니다(값은 저장소에 없음). 배포한 앱은 같은 이름의 Streamlit Secrets를 씁니다.
